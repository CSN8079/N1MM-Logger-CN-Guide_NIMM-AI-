01

初次设置：从安装到能记第一条 QSO

N1MM Logger+ 官方文档把“第一次使用”拆成：安装 → 认识用户文件 → 新建数据库 → 新建日志 → 配置台站与电台 → 测试。

1.1 安装与升级

从官方站点下载完整安装包

下载地址见文末官方资料：N1MM+ 官网的 Full Install。完整安装包包含程序与运行库；之后的小版本更新只需下载 Latest Update。

先安装完整版，再安装最新更新

官方推荐顺序：Full Install → 最新 Update。安装程序会覆盖程序目录，但不会删除用户数据目录里的数据库与配置。

升级前关闭 N1MM 并备份数据

关闭程序后，复制 用户数据目录。再运行更新程序，最后重新启动 N1MMLogger.net.exe。

不要用“绿色版/汉化补丁”覆盖官方程序目录：若确实需要中文界面，优先使用官方 Localization 机制或官方发布的语言文件；替换 DLL/EXE 可能导致数据库或联网功能异常。

1.2 分清两个目录：程序目录与用户数据目录

目录本机路径放什么 / 要不要备份
程序目录程序目录EXE、DLL、驱动、示例文件。升级会覆盖，不要把自己的日志放这里。一般不用备份。
用户数据目录用户数据目录数据库、比赛日志、导出文件、功能键消息、Call History、皮肤等。必须备份。
Databases…\Databases\*.s3dbSQLite 数据库；一个数据库里可以放很多份比赛/日常日志。核心资产。
ExportFiles…\ExportFiles\ADIF、Cabrillo（.LOG）、通用导出文件的默认输出位置。
FunctionKeyMessages…\FunctionKeyMessages\F1–F12 的 CW/SSB/数字模式消息文件。
CallHistoryFiles…\CallHistoryFiles\比赛 Call History（呼号历史）文件，用于自动带出交换信息。
一句话记忆：程序目录出问题可以重装；用户数据目录丢了，通联记录就没了。备份只认用户数据目录。

1.3 新建一个属于你的数据库

N1MM+ 用“数据库 → 日志”的两层结构：一个 .s3db 数据库像一个文件柜，里面可以放很多份“日志（Log）”，每份日志通常对应一次比赛或一类日常记录。

启动 N1MM Logger+

双击桌面快捷方式，或运行 N1MM 程序目录 下的 N1MMLogger.net.exe。若弹出“选择数据库”，先选系统数据库之一也能进入主界面。

File > New Database…

在录入窗口的 File 菜单选择 New Database。程序会打开用户数据目录下的 Databases\ 目录。

给数据库起名

例如 MyCall-DX.s3db（把 MyCall 换成你的呼号）。建议只用英文/数字/短横线，避免中文路径带来的老版本兼容问题。保存后程序会自动切换到新数据库。

以后打开它

再次启动时用 File > Open Database… 选择它；或直接 File > Open Log in Database…，在对话框里切换到该数据库下的某份日志。

数据库 vs 日志：不要为每个 QSO 建数据库。推荐做法：一个个人数据库，里面按比赛/用途建多份日志；跨数据库查找不方便时才考虑拆分。数据库文件可在多台电脑间复制，但同一时间只应有一台电脑打开同一个文件（详见第 4 节）。

1.4 建立第一份日志：Contest Setup 对话框

新建数据库后，用 File > New Log in Database: 你的数据库名 创建日志。弹出的 Contest Setup（比赛设置）对话框是 N1MM 的核心设置入口，日常记录和正式比赛都用它。

选择 Log Type（比赛/日志类型）

点开 Log Type 下拉框，按缩写选择。做正式比赛时务必选对比赛名，它决定计分、重复台判定、交换信息格式和 Cabrillo 输出。不确定时点 Show Setup 查看 N1MM 官方设置页，点 Show Rules 打开主办方规则。

确认起止日期与时间

新日志默认给你下周同一时间。比赛必须按规则填写；日常日志可用默认值或自定。N1MM 内部统一用 UTC 记录 QSO 时间。

填写类别（Category）

操作员类别、波段、功率、模式、叠加类别（Overlay）、台站类别、是否 Assisted、发射机数量等。它们会直接写进 Cabrillo 头部，比赛前必须核对。

填写 Sent Exchange（我发出的交换信息）

只填“你固定要发给对方的交换内容”（如州/省、CQ 分区、序列号起始值、功率等）。不要把 59/599 信号报告写进去——信号报告应放在 F 键消息里。

Operators（操作员）与 Associated Files

填本站呼号/操作员呼号；可选绑定 Call History 文件、功能键消息文件、分区列表等。多操作员时可设置每人独立的功能键消息。

比赛开始后不要再改 Log Type：一旦开始正式日志，改比赛类型会破坏计分与 Cabrillo。若选错，建议新建一份正确日志并把已记录的 QSO 重新导入/录入，而不是硬改。

1.5 台站数据：呼号、网格、分区必须与 LoTW 一致

路径：Config > Change Your Station Data。这里是所有日志共用的“我是谁、我在哪”，会影响交换信息猜测、Cabrillo 头部和 LoTW 上传的正确性。

字段怎么填为什么重要
Call本次操作使用的台站呼号（可能是主呼号，也可能是 /P、/M、特殊事件呼号）Cabrillo 与 LoTW 的台站呼号；必须与 TQSL 的 Callsign Certificate / Station Location 一致
Grid Square4 位或 6 位梅登海德网格，例如 PM01aa（用网格查询工具确认你的实际网格）VUCC、卫星、VHF/UHF 奖励；TQSL 里也要填同一个网格
State / ProvinceWAS/WPX 等需要的州/省影响对方的水/陆地与分区奖励
CQ Zone / ITU Zone按位置填写（N1MM 可自动定位）比赛交换信息、LoTW 位置信息
DXCC Entity / Continent按台站所在地填写决定 DXCC 归属与 LoTW 匹配
多地点操作的核心：换了物理位置（哪怕呼号不变），都要更新 Station Data 里的网格/州/分区；在 TQSL 里也要为这个位置单独建一个 Station Location。否则 LoTW 可能接受 QSO 但无法给对方正确奖励学分，甚至匹配失败。

1.6 配置电台、端口、音频与数字模式

入口：Config > Configure Ports, Mode Control, Audio, Other…（即官方文档中的 The Configurer）。这是 N1MM 最复杂的对话框，按标签页理解就不难：

Hardware（硬件）

Radio 1/2 型号与 COM 端口、波特率；CW/PTT/FSK 端口；SO2R 控制器；旋转器；天线切换等。没有接的设备，端口一律保持 None。

Audio（音频）

声卡输入/输出、录音、数字模式音频路由、SSB 语音键控等。数字模式需要把电台与声卡正确对接。

Other（其他）

Telnet 集群、Call History、分数显示、界面语言、UDP 广播、外部程序接口等。

WSJT / JTDX

WSJT-X / JTDX / JTAlert 的 UDP/TCP 端口与启用开关。默认 WSJT-X/JTAlert UDP 端口是 2333，JTDX TCP 端口是 52001。

先只配 Radio 1

选对电台型号与 COM 口；能读频率、能切波段就算通。双电台/SO2R 之后再配 Radio 2。

配置 CW / PTT（如需要）

用 Winkeyer、串口或并口键控。官方建议优先使用 Winkeyer 类硬件键控，稳定性最好。

配置音频（SSB/数字）

在 Audio 标签选择收发声卡。数字模式还要在 Config > Digital Modes 或对应数字窗口中选择 MMTTY/MMVARI/Fldigi/WSJT-X 接口。

Telnet 集群（可选但推荐）

Configurer 的 Other 或 Telnet 窗口里添加集群地址，看得到 spots 才能用 Bandmap/Available Mults 等比赛利器。

1.7 第一次使用验收清单

✅ 结构

已有自己的数据库；数据库下已有一份测试日志；Databases 目录里能看到对应 .s3db。

✅ 台站

Config > Change Your Station Data 中的呼号、网格、州、CQ/ITU 分区正确。

✅ 电台

转动电台旋钮时 N1MM 频率能同步；用软件能切波段/模式。

✅ 记录

在录入窗口随便记一条测试 QSO（呼号 + 交换 + Enter），能在 Log 窗口看到、能删除。

✅ 消息

按 F1–F12 能看到发送内容；CW/SSB 消息适合你的比赛。

✅ 备份

关闭程序，复制整个 用户数据目录 到一个安全位置。

02

日常使用：记录、查看与修改 QSO

不用比赛时，N1MM Logger+ 也完全可以作为日常日志软件使用；理解录入窗口与几个常用窗口即可。

2.1 录入窗口（Entry Window）就是主界面

所有操作都从 Entry Window 开始。典型记录流程：

输入对方呼号

在 Call 框输入呼号；N1MM 会做重复台检查（Dupe）、呼号检查（Check）并显示分区/历史信息。

输入交换信息

填写 RST/RS、分区、州/省、序列号等比赛交换字段。字段名会随比赛类型变化。

按 Enter / 空格记入日志

默认 Enter 记录并清空；Space 在 ESM（Enter Sends Message）模式下会同时发送对应消息。具体键位可在 Configurer 中调整。

需要改台站/操作员时

用 Ctrl+O 或输入 OPON 切换操作员；多操作员时每人的功能键消息可以独立。

先点“Show Setup”再比赛：Contest Setup 对话框里的 Show Setup 会打开 N1MM 官方对应该比赛的设置说明，是最快的“照着填”资料。

2.2 值得打开的常用窗口

窗口作用什么时候用
Log Window查看本次日志全部 QSO；右键可显示/隐藏列、编辑 QSO核对、改错、统计
Check Window输入呼号时的呼号检查与历史提示减少抄错呼号
Bandmap把 Telnet spots 画到频率轴上，点击即可跳频比赛找台/找系数
Telnet Window连接 DX Cluster，收发 spots比赛与日常追台
Available Mults & Qs列出还没通的系数台/需要的台比赛冲系数
Multipliers / Statistics系数与统计比赛中期查看成绩
Network Status多机联网状态、Station Name、网络消息多操作员/多电脑

2.3 常用快捷键与消息

记录与编辑

Enter 记入日志 · Space ESM 发送 · Ctrl+O 切换操作员 · Ctrl+E 与网络台站对话

功能键 F1–F12

在 Function Key Editor 中编辑；CW/SSB/数字模式各有独立消息文件。比赛中交换信息通常写在 F2/F3 等键里。

宏（Macros）

消息中可用 {EXCH}、{CALL}、{SENTRST} 等宏自动带入当前 QSO 内容，避免手输错误。

窗口与显示

用 Window 菜单或热键打开 Bandmap、Check、Mults 等窗口；皮肤/颜色/字体在 Config > Change Skins, Colors and Fonts 中调整。

2.4 修改、查找与批量处理 QSO

  • 改单条：在 Log Window 中找到该行，右键 → Edit QSO（或对应编辑命令），修改后保存。已有重复台/时间问题时先查清楚再改。
  • 模式显示：若 Log 窗口看不到模式列，右键 → 勾选 Show Mode，再按模式列排序即可找出错记模式的 QSO。
  • 时间错误：官方文档提供了“单条改时间/日期”“批量改时间”“整体平移时间”等命令，比赛后修正时钟偏差很有用。
  • 补录：比赛后可以继续手工补录 QSO；补录前后注意重复台与时间顺序。
  • 删除：删除的 QSO 默认不会出现在 ADIF 导出中；如需导出已删除记录，官方说明可选择 DELETEDQS 日志类型。

2.5 备份与恢复：只做一件事也请做它

关闭 N1MM

确保程序完全退出，数据库文件不被占用。

复制整个用户数据目录

把 用户数据目录 复制到移动硬盘/网盘/另一台电脑，按日期命名，例如 N1MM-backup-2026-10-06。

恢复时整目录还原

把备份目录复制回 Documents\，再启动 N1MM。若只想恢复某次比赛，也可以只复制对应的 .s3db 文件。

不要在 N1MM 运行时用云盘同步 .s3db：OneDrive/Dropbox 的同步可能复制出冲突文件或损坏数据库。要同步，先关闭程序，同步完成后再在另一台机器打开。

比赛日志设置：从选对 Log Type 到生成 Cabrillo

比赛日志的关键不是“记下呼号”，而是让 N1MM 知道这是什么比赛、你报什么类别、交换什么信息，这样计分、重复台判定和 Cabrillo 头部才会正确。

① 新建日志File > New Log in Database
→
② 选 Log TypeShow Setup / Show Rules
→
③ 填 Category操作员/波段/功率/模式…
→
④ 填 Sent Exchange不要写 599
→
⑤ 赛后 CabrilloRescore → Generate

3.1 第一步：选对比赛类型（Log Type）

用对手册确认比赛缩写

例如 CQWW CW、ARRL DX CW、ARRL Field Day、CQ WPX SSB、IARU HF、NAQP、Sprint、VHF/UHF 比赛等。N1MM 的 Log Type 下拉框按缩写排列，可输入首字母快速跳转。

点 Show Rules 与 Show Setup

Show Rules 打开主办方规则；Show Setup 打开 N1MM 官方对应该比赛的中文/英文设置说明。先看规则，再照 Show Setup 填，比问人快也准确。

确认日期与时段

比赛日期按规则填写；N1MM 的时间一律是 UTC。若比赛跨日或有多场次（如 NAQP 两次），建议建立独立日志。

确认比赛级别/波段限制

例如单波段比赛、QRP 比赛、只允许某些模式等。选错类型会导致重复台判定与交换信息全错。

同一台电脑、同一个数据库可以放很多场不同比赛：每场用 File > New Log in Database 新建一份日志即可，比赛互不干扰。不要在同一个日志里混两场比赛。

3.2 第二步：类别（Category）设置

Contest Setup 的顶部区域会把该比赛的类别选项列出来。常见类别含义如下（不同比赛会裁剪）：

类别组常见选项要点
OperatorSingle-Op、Single-Op Assisted、Multi-Op、Multi-Single、Multi-Multi、SWL 等决定是否可以用 Spot/Cluster；多操作员要额外填 Operators
BandAll Band、Single Band（160/80/40/20/15/10/6m…）单波段比赛选错会直接判错组别
PowerQRP、Low Power、High Power功率限制按主办方定义（常见 QRP ≤5W、LP ≤100W、HP 更高）
ModeCW、SSB、Mixed、Digital、RTTY…与 Log Type 互相匹配
OverlayTB-Wires、Classic、Rookie、Youth 等仅在比赛支持时出现；影响附加排名
StationFixed、Portable、Mobile、Rover、Maritime…与你实际台站形态一致；Rover 还要填每个格点的位置
Transmitter / XmitterOne、Two、Multi…SO2R、二发射机等必须如实选择
Time24-hour、6-hour、12-hour 等限时比赛别选错
AssistedAssisted / Non-Assisted使用 DX Cluster/Spot 通常要选 Assisted（除非该比赛另有规定）
Category 会写进 Cabrillo：赛后改类别虽然可以重新生成 Cabrillo，但比赛期间用错类别会影响 N1MM 的行为（例如 Assisted 相关限制）。比赛前就把类别核对一遍。

3.3 第三步：Sent Exchange 与序列号

Sent Exchange 只放“你固定发给对方的交换内容”，例如：

比赛例子Sent Exchange 常见填法说明
CQWW / IARU 等分区交换05（CQ Zone）或 27（ITU Zone）N1MM 常会根据 Station Data 自动猜出

Field Day类别+分区，如 1D + 分区；具体按当年规则Class 与 Section 都要正确

  • 序列号服务器：多机比赛时可由一台电脑作为序列号服务器，保证同一波段/模式序列号不重复（官方文档 "Using a Serial Number Server"）。
  • 分区列表 / Section List：在 Associated Files 中绑定，可帮助检查交换信息是否合法。
  • Call History：绑定后输入呼号可自动带出对方历史交换（如州、分区、姓名），显著减少录入错误。

3.4 比赛中：把 N1MM 当“副驾驶”用

Running / S&P

用 F1 呼叫 CQ（Running）；输入呼号后按空格/回车（S&P）。ESM 模式会让你只按空格就按顺序发送正确消息。

重复台与系数

录入时呼号框颜色/Check 窗口会提示 Dupe；Available Mults & Qs 与 Multipliers 窗口帮你找系数。

Bandmap + Telnet

Cluster spots 显示在频率轴上；点击即跳频，常用颜色区分需要/不需要的台。

SO2R / SO2V

两电台或单机双 VFO 操作时，先按官方 Setup 文档配置 Radio 1/2、音频与切换，再在比赛中使用。

CW / SSB 消息

把常用交换写成 F 键消息，用 {EXCH}、{CALL} 等宏自动替换；比赛中不要靠手打。

数字模式

RTTY/PSK 用 MMTTY/MMVARI；FT8/FT4 通过 WSJT-X UDP 把 QSO 自动送入当前日志（需在 Configurer 的 WSJT/JTDX 标签启用）。

3.5 赛后：计分、生成 Cabrillo、提交

先保护数据

关闭程序并复制数据库；再打开比赛日志操作。官方文档把“赛后保护数据”放在第一节不是没有原因的。

Tools > Rescore Current Contest

按当前比赛规则重新计分，确认 Claimed Score、系数、重复台数量合理。

File > Generate Cabrillo File

N1MM 会生成 你的呼号.LOG，默认放在用户数据目录的 ExportFiles\，也可另存。

检查 Cabrillo 头部

用记事本打开 .LOG，核对：CALLSIGN、CONTEST、CATEGORY-*、CLAIMED-SCORE、OPERATORS、NAME、ADDRESS 等。官方提示：某些比赛要求手动编辑 LOCATION 行来标明你的位置。

按主办方要求提交

多数比赛通过网页上传 Cabrillo；也有比赛接受邮件附件。提交后保留一份 .LOG 与 ADIF 备份。

要交 LoTW 的话，Cabrillo 不是给 LoTW 用的：LoTW 用 ADIF（TQSL 也可读 Cabrillo，但推荐 ADIF）。比赛提交用 Cabrillo；LoTW 用第 5 节导出的 ADIF。

04

在不同地点使用同一套日志

这是最容易出错的部分。先分清“不同时间在不同地点”和“多台电脑同时操作”两种场景，处理方式完全不同。

4.1 三种典型场景与推荐做法

场景典型情况推荐做法注意
A. 同一套设备，不同时间换地点平时在家，周末去 /P、俱乐部台或朋友家操作；呼号可能不变或加 /P继续用同一个数据库；每个地点/每次活动新建一份 Log；换地点时更新 Config > Change Your Station Data；导出后按地点分别签 LoTW不要在两台电脑同时打开同一个 .s3db；换地点必须同步改网格/州/分区
B. 多台电脑同时操作Multi-Op / 多机单操作员 / 俱乐部台，多台电脑同场用 N1MM 的 Network 联网，所有机器共享同一个比赛日志；每台机设置唯一的 Station Name；用一个 Master 数据库版本、比赛类型、Log Type 必须一致；ADIF 可按 Station Name 拆分
C. 分布式 / 远程台站IARU HQ、特殊事件台、VPN 连接的多地台站通过固定 IP 或 VPN 把各台站接入同一个 N1MM 网络；遵守该比赛的分布式类别规则比赛规则可能限制地点/分区/信号数量；先读规则再动手
判断口诀：“同一时间是不是有多台电脑在写？” 是 → 走网络模式（场景 B/C）；否 → 一个数据库、多份日志、按地点更新台站数据（场景 A）。

4.2 场景 B：多台电脑联网共用一份比赛日志

N1MM Logger+ 的网络功能会自动发现同一子网内运行相同版本、相同比赛的电脑，典型的家庭/俱乐部局域网不需要手填 IP。官方文档《Multi-Computer and Multi-Op Contesting》与《The Network Status Window》是权威依据。

统一版本与比赛设置

所有电脑安装相同版本的 N1MM+；打开同一比赛类型（Log Type 一致）的日志；类别（Category）、多操作类别也要一致，否则网络会警告。

把电脑接到同一个局域网

同一个路由器/交换机下；推荐用有线或稳定 Wi-Fi。典型家庭网是同一子网（如 192.168.1.x）。

在其中一台机器上启用网络

在录入窗口打开 Config > Network（或 Configurer 的 Network 标签）启用联网；其他电脑同样开启。程序会自动发现并连接，Network Status 窗口会显示在线台站。

给每台机设置唯一的 Station Name

在 Network Status Window 中为每台电脑设置不同的 Station Name（例如 RUN1、MULT、INBAND）。这个名字会随 QSO 记录保存，也是之后按台站导出 ADIF 的依据。

确定数据库与日志

所有电脑打开同一份比赛日志（推荐一台作为主库，其余通过网络同步）。不要在两台机各自建同名日志后再指望自动合并。

测试后再开机比赛

在一台机记一条测试 QSO，确认另一台的 Log/Network 窗口立刻看到；测试完删除。检查 Ctrl+E “Talk to Another Station” 网络聊天是否可用。

跨网段 / 互联网（场景 C）

官方文档给出两种方式：直接指定外部台站的 IP/端口，或让所有台站接入同一个 VPN（文档提到 SoftEther、Hamachi 等方案）。需要处理防火墙端口放行。

多操作员的语音/消息

每个操作员可用 Ctrl+O 或 OPON 登录；若启用 Per Operator Function Key Messages，每位操作员会在各自子目录里保存独立消息文件。

网络模式不是“共享文件夹”：它是 N1MM 自己的网络协议。把 .s3db 放在网络共享盘上让两台机同时打开，既不是官方多机方案，也极易损坏数据库。

4.3 场景 A：同一数据库、不同地点，如何正确拆分与导出

LoTW/TQSL 的硬性要求：一个将要签名的文件里的所有 QSO 必须属于同一个台站呼号、同一个操作地点。所以“同一套日志”在 N1MM 里可以统一管理，但导出给 TQSL 时要按地点拆分。

换地点前更新 Station Data

Config > Change Your Station Data：改成该地点的呼号（含 /P 等）、网格、州/省、CQ/ITU 分区、DXCC 实体。换地点后再改回来，别忘记。

给每个地点建独立 Log

例如 ARRL-DX-CW-Home、ARRL-DX-CW-Portable。即使呼号相同，只要物理地点不同，就建议分开，导出时天然按地点分流。

导出全部或部分 QSO

导出全部：File > Export > Export ADIF to file…。只导出部分：先在 Log Window 选中需要的 QSO，再执行导出（N1MM 支持导出选中记录；不同版本菜单文字可能是 “Export ADIF to file” 或带 Selected）。

多机环境按 Station Name 导出

官方文档提供 Export ADIF to file by Multi-User Station Name：在多用户环境下，按 Station Name 把所有该台站的 QSO 导出为一个 ADIF。先用 Network Status 提供 Station Name，再选文件名。

需要合并时用 ADIF 合并

官方合并流程：每台记录电脑 File > Export > Export ADIF to file；确认各文件的 CONTEST_ID 完全一致；把 ADIF 汇总后用 File > Import 导入同一份新日志。不要用 Excel/Cabrillo 手工合并，除非你很清楚格式。

【多地点的标准工作流示例】
1) Home 地点：Config > Change Your Station Data → 填入你的实际网格、州/省、CQ/ITU 分区
   File > New Log in Database → 建立 Home 日志 → 操作并记录
2) 便携地点：先更新 Station Data 为便携网格/位置
   File > New Log in Database → 建立 Portable 日志 → 操作并记录
3) 赛后分别导出：
   Home 日志   → File > Export > Export ADIF to file… → home.adi
   Portable 日志 → File > Export > Export ADIF to file… → portable.adi
4) TQSL 中为两个地点各建一个 Station Location：
   CALL-Home、CALL-Portable
5) 分别签名上传：
   tqsl -d -u -a compliant -l "CALL-Home"    "home.adi"
   tqsl -d -u -a compliant -l "CALL-Portable" "portable.adi"
临时在朋友家操作？也可以继续用你的数据库，但一定要新建一份 Log，并在该 Log 有效期间把 Station Data 改为朋友家的位置。比赛规则是否允许你这样做（例如是否需要 /P、是否算不同台站），以比赛规则为准。

4.4 规则与红线：这一节能帮你少走很多弯路

🚫 一个 TQ8 文件不能混地点

ARRL 官方明确：提交给 LoTW 的一个文件中的所有 QSO 必须使用同一个台站呼号和同一个操作地点，才能用同一个 Callsign Certificate 和 Station Location 签名。混了就必须拆分。

🚫 不要把同一 .s3db 放在共享云盘同时打开

N1MM 不是并发文件数据库。多机同时写必须走 N1MM 网络；单机换地点可以用复制/备份，但要先关闭程序。

⚠️ 比赛规则优先于软件能力

软件能合并日志，不代表比赛允许你跨地点合并成绩。很多比赛规定单操作员的所有 QSO 必须在同一地点完成；Field Day、IARU HQ、Rover、DX 远征等各有特殊规则。

⚠️ LoTW 与比赛提交是两条线

LoTW 负责“确认 QSO”；比赛成绩提交用 Cabrillo 给主办方。你可以按地点分别上传 LoTW，但比赛成绩必须按该比赛的规则申报。

权威依据：N1MM 官方《Multi-Computer and Multi-Op Contesting》《The Network Status Window》《Operating a Contest（How to Merge Contest Logs）》；ARRL LoTW 官方《Multiple Callsigns and Operating Locations》《Defining a Station Location》《Submitting QSOs》。链接见文末。
05

签名并上传到 ARRL Logbook of The World（LoTW）

关键要记住：N1MM 负责产生 ADIF，TQSL 负责用你的呼号证书签名，LoTW 负责接收和确认。N1MM 本身不做数字签名。

5.1 先搞懂四个核心概念

1. LoTW Account（LoTW 账户）

ARRL 的在线服务账户，用用户名/密码登录，查看已提交、已确认的 QSO，并申请奖项学分。申请呼号证书后 ARRL 会发给你账户密码。

2. Callsign Certificate（呼号证书）

由 ARRL 签发、绑定你呼号的数字证书（含私钥），用于证明“这条 QSO 确实由这个呼号提交”。每个呼号一张，有效期 3 年，可续期。

3. Station Location（台站位置）

在 TQSL 中定义的操作地点：呼号 + 网格 + ITU/CQ 分区 + IOTA + DXCC 实体 + 州/县等。对方要靠它获得 VUCC/WAS 等奖励学分，必须准确。

4. TQSL 与 .TQ8 文件

TQSL 是 ARRL 提供的免费签名/上传工具。它读取 ADIF（或 Cabrillo），用呼号证书签名，生成加密的 .tq8 文件并上传到 LoTW。

5.2 安装 TQSL 并申请呼号证书

下载安装 TQSL

从 ARRL 官方 TQSL Download 页面下载安装（本页整理时官方最新为 TQSL 2.8.6，支持 Windows/macOS/Linux）。不要从第三方站点下载。

在 TQSL 中请求呼号证书

打开 TQSL → Callsign Certificate 菜单 → Request New Callsign Certificate → 输入呼号、选择 DXCC 实体、填写姓名/地址/邮箱等，按向导提交。

等待 ARRL 处理

美国呼号通常按 FCC 数据库自动核对；非美国呼号可能需要提交操作执照等证明文件（官方 "Required Documentation"）。处理完成后 ARRL 会把账户密码和证书发到你的邮箱。

在同一台电脑上接受证书

官方明确：必须用申请证书的那台电脑接受证书。所以建议指定一台“主控电脑（Master）”，以后申请/续期证书、维护 Station Location 都在这台机器上做。

登录 LoTW 账户验证

用 ARRL 邮件中的用户名/密码登录 LoTW，确认能查看账户；再回到 TQSL 继续定义台站位置。

证书有效期 3 年：到期前 ARRL 会提前数周发邮件提醒，可在 TQSL 中续期。不要等过期后才处理；过期证书会导致上传被拒绝。

5.3 创建 Station Location（每个物理地点一个）

TQSL → Station Locations 标签

点击 Create a new Station Location，打开 Add Station Location 对话框。

选择呼号证书 / DXCC 实体

选择对应呼号；若把 Call Sign 设为 [None]，需要勾选允许并选择 DXCC 实体，TQSL 会在上传时按 DXCC 匹配证书。

填写网格与分区

按官方要求填：Grid Square（4 位或 6 位）、ITU Zone、CQ Zone、IOTA 参考号（如适用）。官方还支持用逗号分隔的多个网格（如移动/多点操作）。

填写州/县等奖励信息

美国台站按需填 State、County；其他地区按 WAS/VUCC 等奖励要求填写。信息越完整，对方越容易拿到学分。

命名并保存

建议“呼号+地点”，例如 MYCALL-Home、MYCALL-Portable-GRID。以后签名时用这个名字 -l 指定。

Station Location 与 N1MM 的 Station Data 必须一致：呼号、网格、分区、州/县/DXCC 实体要对应同一个物理位置。一个 Station Location 只能代表一个地点；多地操作就建多个。

5.4 从 N1MM 导出 ADIF

确认当前日志正确

打开要上传的那份比赛/日常日志；确认 Station Data 与 Contest Setup 正确。

File > Export > Export ADIF to file…

选择保存位置（默认 用户数据目录 下的 ExportFiles\）与文件名，例如 arrl-dx-cw-2026.adi。N1MM 官方 FAQ 的 LoTW 答案就是这一条路径。

只导出一部分 QSO（可选）

先在 Log Window 选中需要的 QSO，再执行导出；多机环境可用 Export ADIF to file by Multi-User Station Name 按台站名导出。

核对 ADIF

用记事本打开 .adi，确认有 <CALL:...>、<QSO_DATE:...>、<TIME_ON:...>、<BAND:...>、<MODE:...> 等基本字段；LoTW 至少需要对方呼号、UTC 日期时间、波段、模式。

导出前先 Rescore：虽然不是 LoTW 必需，但比赛后先 Tools > Rescore Current Contest 再导出，能避免分数/系数与最终提交不一致。

5.5 用 TQSL 签名并上传

方式一：图形界面（推荐新手）

打开 TQSL

选择 Sign a log and upload it automatically to LoTW（或 “Sign an existing ADIF or Cabrillo file”）。

选择你的 ADIF 文件

选中刚才 N1MM 导出的 .adi。

选择 Station Location

选择与该批 QSO 的呼号/地点完全一致的 Station Location。TQSL 会显示将使用哪张呼号证书。

签名并上传

TQSL 生成 .tq8 并上传；屏幕上会显示 “Log uploaded successfully with result ... File queued for processing”。

保存 .tq8（可选）

若网络不稳定或需要离线签名，可先保存 .tq8，之后再上传或通过其他电脑提交。

方式二：命令行（适合批处理/多地点分别签名）

TQSL 官方提供命令行接口。核心参数含义：-l 指定 Station Location，-u 签名并上传，-a 选择对重复/超范围 QSO 的处理策略，-x 完成后退出，-d 输出调试信息。官方示例：

tqsl -d -u -a new -x -l "CQWW Portable" "cqww log.adi" 2>results.txt
# 用指定的 Station Location 签名并上传
tqsl -d -u -a compliant -l "MYCALL-Home" "n1mm-export.adi"

# 只签名保存 .tq8，不立即上传（示例：-u 换成只生成输出文件的方式请查官方 CLI 参考）
# 输出文件默认与输入文件同名、扩展名为 .tq8
参数会随 TQSL 版本变化：执行前请在终端运行 tqsl --help，或查阅官方 TQSL Command Line Interface。上面的命令来自 ARRL 官方示例，可直接照抄格式，但站名/文件名要换成你自己的。

5.6 多地点 / 多呼号：LoTW 的正确签名策略

情况需要几张 Callsign Certificate需要几个 Station Location怎么签
同一呼号、同一地点1 张1 个直接签
同一呼号、多个地点（家 / 便携 / 朋友家）1 张每个地点 1 个按地点拆 ADIF，分别用对应 Station Location 签
不同呼号、同一地点（旧呼号 / 新呼号 / 特殊事件呼号）每个呼号 1 张按呼号+地点各建按呼号+地点拆 ADIF，分别签
DX 远征 / 多地移动主呼号证书；多呼号要额外申请每个操作地点一个按“呼号+地点+日期”拆分；官方 DXpedition 指南建议逐段签
ARRL 官方原文要点：提交给 LoTW 的一个文件中的所有 QSO，必须使用同一个台站呼号、同一个操作地点，才能用同一个 Callsign Certificate 与 Station Location 签名。若文件里混了多个呼号或多个地点，必须用日志软件或文本编辑器拆成多个文件，再分别提交。
拆分小技巧：N1MM 的多机环境优先用 Export ADIF to file by Multi-User Station Name；同机多地点则建议一开始就按地点分 Log，导出时天然分离，避免事后手工切分 ADIF。

5.7 验证上传、处理未确认与证书续期

登录 LoTW 查看已提交 QSO

ARRL LoTW 网站 → Your QSOs → 查看 Submitted/Accepted。刚上传的文件会先排队处理，可在 ARRL 的 Logbook Queue Status 页面查看队列。

为什么对方还没确认？

LoTW 的确认是双向的：只有对方也把匹配的 QSO 上传后才会显示确认。若长期未确认，检查呼号、UTC 日期/时间、波段、模式、卫星名等字段是否与对方一致，以及你选的 Station Location 是否正确。

重复上传会被标记为 Duplicate

TQSL 会提示 “some QSOs were duplicates or out of date range”，这是正常保护机制，不会重复计数。若你确实改了 QSO，需按 LoTW 的“更正”流程处理。

证书续期

TQSL → Callsign Certificate → Renew；或按 ARRL 邮件提示操作。续期仍在“主控电脑”上完成，完成后把 TQSL 备份恢复到其他电脑。

换电脑

官方推荐：在主控电脑上 TQSL → 创建 Backup File；把备份复制到新电脑；在新电脑 TQSL 中 Restore，即可带上呼号证书、私钥、Station Location 与偏好设置。

常见问题 FAQ

点开每条查看；更具体的问题可以直接问右下角 AI 助手。

N1MM Logger 和 N1MM Logger+ 是同一个软件吗？

不是。经典版 N1MM Logger 早已停止开发；现在使用和支持的是 N1MM Logger+（常写作 N1MM+），你现在安装的就是 Plus 版本（页面顶部会自动显示检测到的版本号）。网上老教程里的菜单/流程可能仍可用，但数据库结构与功能请以 N1MM+ 官方文档为准。

我还没有呼号证书，LoTW 第一步做什么？

先装 TQSL → 在 TQSL 里 Request New Callsign Certificate → 等 ARRL 邮件 → 在申请证书的同一台电脑上接受证书 → 定义 Station Location → 再上传 QSO。没有证书，TQSL 无法签名。

参考：LoTW Getting Started

我在两个不同地点操作，能用同一套 N1MM 日志吗？

可以统一管理，但要满足两个条件：(1) 每个物理地点在 N1MM 中更新正确的 Station Data（网格/州/分区/DXCC）；(2) 导出给 TQSL 时按地点拆成不同 ADIF，并用各自的 Station Location 分别签名。

最稳妥的做法是每个地点新建一份 Log；多机同场则用 N1MM 网络模式，并用 Station Name 区分台站后按名称导出。

两台电脑能同时打开同一个 .s3db 数据库吗？

不要这样做。N1MM 的多机方案是它自己的 Network 功能，而不是共享同一个数据库文件。把 .s3db 放在 OneDrive/共享盘上让两台机同时打开，极易造成冲突或数据库损坏。

正确做法：多机同场 → 启用 N1MM Network；非同时 → 关闭程序后复制数据库，或在另一台机器上用 ADIF 合并。

Cabrillo 和 ADIF 有什么区别？该交哪个？

Cabrillo（.LOG）是比赛主办方要求的成绩提交格式，包含比赛类别、声明分数与 QSO 行，用 N1MM 的 File > Generate Cabrillo File 生成。ADIF（.adi）是通用通联交换格式，用 File > Export > Export ADIF to file… 生成，交给 TQSL 签名后上传 LoTW。

一句话：比赛提交用 Cabrillo，LoTW 用 ADIF。

比赛日志被退回，最常见原因是什么？
  • Sent Exchange 里多写了 5NN/59；
  • Log Type 选错（相近比赛名）；
  • Category（组别/功率/波段/Assisted）与申报不符；
  • Cabrillo 头部缺 LOCATION、OPERATORS 等信息；
  • 时间不是 UTC，或起止日期不对。

处理：改设置 → Tools > Rescore Current Contest → File > Generate Cabrillo File → 用记事本核对头部 → 重新提交。

怎样把 WSJT-X / JTDX / JTAlert 的 QSO 自动送进 N1MM？

在 Configurer 的 WSJT/JTDX Setup 标签启用对应端口：WSJT-X/JTAlert 默认 UDP 2333，JTDX 默认 TCP 52001。勾选 Enable 后（可能需要重启 N1MM）即可接收。官方文档《Sending Log Data to N1MM Logger》给出了支持的 ADIF 字段与数据格式。

数据库打不开 / 提示不是日志数据库怎么办？

先不要反复尝试写操作。关闭 N1MM，把 Databases 目录整个复制一份留底；检查是否误选了 .s3db.bkup 或系统数据库；若主文件损坏，可尝试用同名 .bkup 备份恢复（先复制一份备份文件再改名为 .s3db）。同时查看用户目录下的 LogError.txt 与 Diagnostics 文件夹，必要时在 N1MM 官方支持站提交工单。

怎样备份、换电脑或重装系统？

N1MM 侧：关闭程序，复制整个 用户数据目录；新电脑安装同版本 N1MM+ 后，把这个目录放回 Documents 覆盖。

TQSL 侧：在旧电脑 TQSL 中做 Backup File，在新电脑 Restore，这样呼号证书、私钥、Station Location 与偏好设置都会带过去。不要把私钥单独用邮件明文发送。

换了呼号，旧 QSO 怎么办？

N1MM 里可以继续用原数据库/日志保存历史 QSO；新呼号建议新建日志，并把 Station Data 改为新呼号。LoTW 侧需要为新呼号申请新的 Callsign Certificate（并可能需要更新 LoTW 账户的主呼号），旧呼号证书仍可用于上传旧 QSO。

参考：LoTW Changing Your Primary Callsign、Multiple Callsigns and Operating Locations

不同地点需要分别申请呼号证书吗？

不需要——呼号证书绑定的是呼号，不是地点。地点由 Station Location 表达。同一呼号在不同地点操作：一张证书 + 多个 Station Location。不同呼号才需要各自的 Callsign Certificate。

N1MM 能直接上传 LoTW 吗？

按 N1MM 官方 FAQ，标准流程是：N1MM 生成 ADIF（File > Export > ADIF）→ 用 TQSL 处理并生成 .TQ8 → 上传到 LoTW。签名与上传由 ARRL 的 TQSL 完成，这也是官方支持的路径。

DeepSeek API Key 安全吗？会不会泄露我的日志？

本页默认把 API Key 保存在你浏览器的 localStorage，只发送给 DeepSeek API（https://api.deepseek.com）或你本地运行的代理；网页不会读取或上传你的 .s3db/ADIF 文件。请不要在公用电脑上保存 Key；如果介意，可以只在本机使用，或改用自己搭建的代理并随时轮换 Key。
